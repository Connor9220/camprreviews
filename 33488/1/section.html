What the PR changes

Path.Geom.isVertical(edge) for B-spline and Bezier curves:

  • before: "vertical if the curve's start and end points are stacked in Z". A closed curve has start = end, so it always counted as vertical. The check also used the untrimmed curve, not the edge.
  • now: Bezier curves are converted to a B-spline over the edge's parameter range. For B-splines, a planar edge is vertical when its plane is vertical (findPlane(), the same rule circles use). Other edges are split into arcs and lines (toBiArcs, tolerance min(0.1 * length, 0.1)), and the edge is vertical only if every piece is.
  • The old, commented-out Bezier tests are switched back on, and B-spline line and circle tests are added.

Minor finding: B-spline face test now flips for curved edges in a vertical plane

What it does. isVertical(face) for a BSplineSurface face counts its edges: a face is vertical when exactly 2 of its 4 edges are vertical. That rule assumed "vertical edge" meant "straight up". With this PR, a curved edge that lies in a vertical plane also counts as vertical, so:

  • a fillet along a top edge (2 straight horizontal edges + 2 quarter arcs in vertical planes) now has 2 "vertical" edges and is called vertical. On main it was not vertical, which is correct.
  • an arch-shaped flat end face (bottom line, two straight sides, arched top) now has 3 "vertical" edges and is called not vertical. On main it was vertical, which is correct.

Impact. Adaptive with Model Aware skips "vertical" faces when it projects the model (Adaptive.py:845). On a scaled block 60×50×20 with R6 fillets on the two long top edges (Adaptive, Outside, Model Aware, down to Z 2), the toolpath was identical on main and the PR, because the bottom face still covers the outline. The other callers are the Select Loop helpers (PathUtils.horizontalFaceLoops / facesAtHeight), which only change what gets selected. So this is a wrong answer from the changed function with no toolpath damage found. Possible fix: in the BSplineSurface branch, count only straight edges that point in Z (the old meaning).

Repro. Part.makeBox(60,40,20), fillet the two top edges along X (R6), then transformGeometry with a matrix scaled (1, 1.25, 1). Path.Geom.isVertical(shape.Faces[2]) (a fillet face) gives False on main and True on the PR.

sliptonic's AI review (10-26) against the current head

  1. "Vertical" has two meanings; biarc pieces inherit both.
    • Inclined straight part in an XZ-plane spline returns False: fixed. The author added the suggested findPlane() check, so a planar curve in a vertical plane is now vertical (the xz_polyline_deg1 row above).
    • Non-planar 3D curve whose arcs have different horizontal axes returns True: still stands, edge case only. Reproduced with an XZ arc joined to a YZ arc at a sharp corner. main says not vertical, the PR says vertical, and Model Aware Adaptive would drop such an edge. Smooth real-world 3D edges (helix, wavy curve, cylinder–cylinder saddle) all come out not vertical, because their biarc pieces lie in tilted planes. Not listed as a finding.
  2. Bezier branch ignores the parameter range: fixed. It now uses toBSpline(*obj.ParameterRange). The B-spline branch trims too, which also fixes main's use of the untrimmed curve's end points (half-circle row above).
  3. Inline: 0.1 tolerance is a magic number, add a comment: unchanged. No comment yet. Cosmetic.
