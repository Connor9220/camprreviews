TL;DR

  • Fix confirmed: with Keep Tool Down or Lead-In/Out, links next to an Avoid Face no longer hop up over plain stock, and lead-in arcs beside it are no longer replaced by straight plunges. Cutting passes are unchanged.
  • Minor finding: when Avoid Faces Overlap is more than half the avoid face's width, the new Safe STL boundary collapses. Every recompute then prints two warnings ("extend the boundary", "holes will be lost") that the user can't act on. Main prints nothing in the same setup.
  • Same cause, ring-shaped avoid faces: the Safe STL keep-out comes back as a solid disk over the ring's open centre instead of nothing. In my test op this did not change the toolpath.

What the PR does

Before this PR, one Avoid Faces boundary, grown by the tool radius, fed two consumers:

  1. the machining mask (the hole cut out of the area the tool centre may visit), and
  2. the Safe STL "keep-out pillar", a flat face at Start Depth + 0.1 used by Keep Tool Down and Lead-In/Out.

The OCL drop-cutter already adds the tool radius when it tests against the Safe STL. So the pillar counted the tool radius twice, and the tool lifted one tool radius too early all around each avoid face.

build_avoid_boundary() now takes tool_radius and returns two shapes: the mask boundary (offset tool_radius - overlap + ε, same as before) and a new pillar boundary (offset -overlap + ε). The pillar is built only when the Safe STL is needed.

Avoid Faces Overlap

  • Overlap 2: mask Ø18.05 and pillar Ø12.05, both shrunk by 2 mm as intended. Cut boundary r=9.03 on both sides.
  • Negative values are clamped to 0 by the property, as before.
  • Overlap 8.5 or 9 (more than the 8 mm hole radius): the mask is fine (Ø4.05) and the pillar collapses to None. That is the right result, but the way there is noisy (finding 1).

Finding 1 (minor): collapsing pillar prints misleading warnings and can come back with the wrong shape

build_avoid_boundary() builds the pillar with build_optimized_boundary(prepared_faces, -avoid_overlap + epsilon, …). Once the overlap is more than half the avoid face's width, that inward offset has nothing left. create_boundary_face() then treats the empty result as a failure:

  1. _boundary_via_area warns "Offsetting the Model faces resulted in an empty shape. Extend the boundary if the selected faces are too small."
  2. It falls back to _boundary_via_techdraw, which warns "Falling back to TechDraw outline extraction, which cannot preserve inner wires (holes). Any holes in this selection will be lost."

Both warnings are printed on every recompute of the op. The mask, the part the user controls with this setting, is fine, and main prints nothing for the same setup (verified side by side at 8.5 mm). Before this PR the only offset was tool_radius - overlap, so it collapsed only when the overlap exceeded the half-width plus a whole tool radius. Now it happens as soon as the overlap exceeds the half-width, which is common with narrow avoid faces such as rib tops or slot floors.

For a ring-shaped avoid face, the TechDraw fallback finds something. It takes the outer outline (losing the inner hole) and shrinks it, so the pillar comes back as a solid disk over the ring's open centre. Test: ring 7–10 mm radius, overlap 2, tool Ø6 gives a single-wire disk Ø16.05, area 202 mm², where no pillar was expected. See ring_pillar.png. In a real op (a boss inside a ring-shaped groove floor, Line pattern, Keep Tool Down) the toolpath came out the same on main and the PR, so I could not show a path change from this. It is a wrong shape feeding the Safe STL, not a demonstrated gouge.

Repro: Planar Surface on a face with a Ø16 hole, hole floor as the last (avoid) face, Keep Tool Down on, Avoid Faces Overlap = 8.5 mm, recompute. Watch the Report view.

Suggested fix: for the pillar, an empty inward offset just means "no pillar". Build it without the TechDraw fallback, or skip it when avoid_overlap is at least the face's inradius, and don't warn.
