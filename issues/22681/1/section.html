TL;DR

  • On current main (38431477604) the chamfer bit opens in the Tool Parameter Editor with no errors and can be edited.
  • The overconstraint is gone: the outer Diameter is now worked out from tip diameter, cutting edge height and angle. It is read-only and no longer shown in the editor.
  • The table now says "Tip diameter (D)", which matches the drawing. α is the included angle in both the table and the drawing, and the operations use it that way.
  • One small point is still there: the sample bit is called "45 Deg. Chamfer" but has a 45° included angle (22.5° per side), not the 90° included angle of a usual 45° chamfer mill.

What was tested

Tested on FreeCAD main 38431477604 (2026-10-14), built from source, with the GUI on an off-screen display. No PR applied.

1. The reporter's steps: open the shipped chamfer bit in the editor

I loaded the shipped 45degree_chamfer.fctb ("45 Deg. Chamfer"), added it to a document and opened it in the Tool Parameter Editor (ToolBitEditor).

Item Reporter's build (July 2025) Main today
Fields angle, height, Diameter (D) = 12.33, length, shank, Tip diameter = 5.00 angle, height, length, shank, Tip diameter (D) = 5.000; Diameter is not shown
Drawing "D" at the tip, but the table's "Diameter (D)" was the outer diameter at the tip, and the table's "(D)" is the tip diameter
Outer diameter typed in, could disagree with the geometry derived as TipDiameter + 2·h·tan(α/2) = 10.26 mm, ReadOnly in the property view
Errors in Report view n/a none

The .fctb still stores Diameter: 12.3323 mm, but the value is recomputed when the bit loads, so that stale number has no effect. The tool solid matches the derived value: it measures 2.51 mm radius at the tip and 5.13 mm at h = 6.35 mm, a slope of tan 22.5°, so the bounding box is about 10.26 mm across.

The fix came from commit 48de20c8fd6 "CAM: Make chamfer Diameter derived from tip and cutting geometry" (Aug 2026). Commit e0765cfb36e then fixed ToolBit units, precision and the task panel.

2. Editing the bit

In the open editor I typed 90 into "Cutting edge angle (α)" and pressed Enter. The derived Diameter changed to 17.70 mm (5 + 2 × 6.35 × tan 45°), the tool solid grew to match (bounding box ±8.85 mm), and no errors appeared.

3. Old-style chamfer bit (reporter's second screenshot)

I built a .fctb with only the old parameters (Cutting Edge Height, Diameter 12.33, Length, Radius 4.00, Shank Diameter), as in the reporter's older screenshot, and loaded it on main:

  • It loads and recomputes with no errors.
  • The missing angle and tip diameter get the shape's defaults (60°, 5 mm). Both are now editable in the editor; the reporter said α could not be reached in that older version.
  • The derived Diameter is 12.33 mm. It replaces the stored value and happens to match it at 60°.
  • The old Radius stays as a read-only leftover row. It is harmless but adds clutter.

4. Is α the cutting angle or the full sweep?

On main, α is the included (full) angle everywhere: the drawing, the derived diameter formula, the tool solid, and Deburr (Path/Op/Deburr.py uses tan(angle/2)). V-bits use the same convention. The label "Cutting edge angle (α)" is consistent with the drawing, so I don't count this as a bug.

What is still a bit misleading is the sample bit's name. "45 Deg. Chamfer" has α = 45° included, which cuts a bevel 22.5° from vertical. A shop "45° chamfer mill" is normally 90° included and cuts a 45° bevel. With the sample bit and Width = 1 mm, Deburr goes 2.41 mm deep instead of 1 mm. This is a naming problem in the sample data, not a broken editor.

5. Drilling picking a chamfer bit for 5 mm holes

Hole operations compare holes against Tool.Diameter. On main that value is the derived outer diameter (10.26 mm for the sample bit), not the 5 mm tip, so the scenario the reporter described no longer follows. I did not run a separate Drilling job for it.

Not tested

  • The reporter's own old library file (none was attached). I built an equivalent from the screenshot instead.

Side note

For an old-style bit with no shape-type, the editor's "Toolbit Type" field shows Chamfer.Fcstd instead of Chamfer. This is cosmetic and separate from this issue.
