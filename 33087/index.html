PR #33087 - CAM: OpArea - Fix ZigZag start point (tarman3)

TL;DR

  • Fix confirmed: Pocket/MillFace ZigZag now starts each step-down where the previous one ended (stay-down step to the next level), restoring the pre-#30402 behavior. Author's file: rapid 160.0 -> 88.9 mm, retracts 3 -> 2.
  • Only ZigZag output changes: Offset, Helix, Line, Grid and No clearing are byte-identical to main, for both cut modes, on every test file.
  • No defects found. Full CAM suite passes (1990 tests, OK).

What the PR changes (Path/Op/Area.py)

  • ZigZag open wires now go through the same branch as closed wires: nearest wire to the current end point, start = self.endVector, so Path.fromShapes begins at the nearer end of the zigzag.
  • reverseOpenWire (start an open wire from its last vertex) is now set only for Climb with Line or Grid; it used to apply to ZigZag too.
  • Docstring typo fix in setParamsDebug.
