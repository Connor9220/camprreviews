TL;DR

  • The core fix works: thickening a zero-length curve now gives the tool circle. On main it returns an empty area, which is the undefined list::front() call behind #34148. All 2139 CAM tests pass.
  • New bug in the third commit: rest machining now counts a straight plunge as cleared, but only if no other vertical move happens at the same spot. A plunge followed by a retract at the same XY adds two identical circles, and the even-odd union cancels them, so nothing is counted.
  • Rest-machining output can change slightly. On the pocket-island model, one rest-machined MillFace op went from 982.6 mm to 1057.2 mm: the same sub-millimeter scallops, joined by one extra 55 mm pass along the stock edge.

What the PR does

  1. libarea/AreaClipper.cpp (CArea::NaiveOffset): the "single point becomes a circle" block now runs after the segment loop, triggered by an empty cPos. A curve made only of zero-length segments becomes a circle instead of reaching cPos.m_vertices.front() on an empty list.
  2. App/Area.cpp (ClearedAreaSegmentVisitor::line): a G0/G1 move with no XY travel calls point() at its lower end, which adds a tool circle to holes, instead of a zero-length segment.
  3. Two new tests, test_thicken_point and test_thicken_zero_length.

Defect

A plunge followed by a retract at the same spot is not counted as cleared. line() now sends every vertical G0/G1 move to point(), using the move's lower end. A plunge and the retract right after it both end at the same bottom point, so holes gets two identical circles. getClearedArea() merges them with result.Union(holes), and CArea::Union clips with FillRule::EvenOdd (AreaClipper.cpp:286), so identical circles cancel in pairs. The new "count the plunge" behavior therefore works only when a spot has an odd number of vertical moves. This is never worse than main, which counts none of these, but the third commit's change is lost in the drill-like case it would help most. Measured with Path.getClearedArea(6.0, 0.0, bbox):

Path main PR
Plunge Z+5 to Z-3, nothing else 0 28.84 mm² (one circle)
Plunge, then retract at the same XY 0 0
Two plunge+retract pairs at different XY 0 0
Cut 10 mm, then plunge+retract elsewhere 89.44 89.44 (plunge lost)
Plunge from Z-1 to Z-3 (both below zmax), nothing else 0 28.84
G81 twice at the same XY 0 0 (also on main: same even-odd union)

Repro: build Path.Path from G0 X20 Y20 Z5, G1 X20 Y20 Z-3, G0 X20 Y20 Z5, call getClearedArea(6, 0, FreeCAD.BoundBox(-50,-50,-50,50,50,50)), and the shape has no wires. Remove the last line and you get the circle. Possible fixes: merge holes with a non-zero or positive fill (Clip(ClipType::Union, holes, FillRule::NonZero)), which also fixes the existing double-G81 case, or call point() only for downward moves.
